## 第一章：起点 — 两个开源工具

### 1.1 它们是什么

教授让我学习两个开源项目：

**3D-ICE**（EPFL 开发，C 语言 FVM 仿真器）
- 功能：输入芯片布局 + 材料 + 冷却方式，输出 3D 温度场
- 优势：物理精确，支持微通道液冷模型
- 劣势：单次仿真慢（分钟级），无法实时

**DeepOHeat**（UCSB + Cadence 联合，Python/PyTorch DeepONet AI 求解器）
- 功能：用神经网络预测 3D-IC 温度场
- 训练方式：PINN（物理信息神经网络）——无数据，纯物理方程约束
- 优势：推理极快（毫秒级），零训练数据
- 劣势：精度受限于物理方程的简化假设

### 1.2 为什么要结合它们

| | 3D-ICE | DeepOHeat |
|---|---|---|
| 精度 | 高（真实物理） | 中（简化方程） |
| 速度 | 慢 | 极快 |
| 液冷支持 | 有 | 无 |
| 数据需求 | 每次重跑 | 零数据 |

**核心洞察**：两者互补——用 3D-ICE 的高精度数据教会 DeepOHeat 的 AI 模型，得到一个又快又准的仿真替代品。

## 第二章：方向选择 — 为什么选"物理预训练 + 数据微调"

### 2.1 五个可能方向

1. **A：纯 PINN** — 只用 DeepOHeat，不改训练方式
2. **B：纯数据驱动** — 只用 3D-ICE 数据训一个神经网络
3. **C：物理预训练 + 3D-ICE 微调** — PINN 无数据打底，再用少量仿真数据校准
4. **D：主动学习** — 让 AI 自己挑最有价值的 case 来仿真
5. **E：替代架构** — 换 Transformer/CNN 等替代 DeepONet

### 2.2 选定方向 C 的原因

- A 天花板太低——方程精度就是极限
- B 需要海量仿真数据——太贵
- C 是否更优是待验证假设，不能预设“组合最优”
- D、E 太复杂，先验证 C 再说

**一句话**：先用傅里叶热传导方程做无数据预训练让 AI 掌握热传导基本规律，再用少量 3D-ICE 仿真数据微调把精度从满足方程调到逼近真实。

## 第三章：校准攻坚 — 归一化规则的推导

### 3.1 问题

DeepOHeat 代码里所有数值都是无量纲的（k=0.2、温度 u、坐标 [0,1]），3D-ICE 输出是物理单位（K、W）。怎么对应？论文没有写。

### 3.2 反推过程

从代码和论文交叉验证，逐步反推：

**特征尺度**：
- L = 1mm（芯片 x-y 尺寸）
- ΔT = 25K（特征温升）
- T_ref = 293.15K = 20°C

**温度**：`u = (T - 293.15) / 25`
- 代码证据：`prototype.py:123` 行 `u = 293.15 + 25*u`
- 物理验证：u=0.2 → 298.15K（论文给出的 Tamb）

**功率**：`v = P_cell_mW / 0.00625`
- 论文 V.A.1 明确："one-unit power = 0.00625(mW)"
- 代码证据：`file_parser.py:80` 行 `sensor /= 0.00625`
- 物理验证：v=1 → 2500 W/m² → 每格 0.00625 mW ✓

**热导率 k=0.2 的双重含义**：
- PDE 残差中：纯权重因子（k∇²u=0，无源时 ∇²u=0 不依赖 k）
- Robin BC 中：`h̃ = k_phys/(h·L) = 1/Bi`
- 验证：0.1/(500×0.001) = 0.2 ✓

**Robin BC（硬编码的坑）**：
- `loss_robin` 里硬编码了 `u - 0.2 + direction*k*jac = 0`
- 这个 0.2 = (298.15-293.15)/25 = u_amb
- 如果要换环境温度，必须改源码！

### 3.3 学到什么

- **论文不等于代码**：归一化公式全在代码里，论文一句没提
- **代码不会骗人**：硬编码的常数、parser 里的除以 0.00625，都是线索
- **交叉验证最关键**：每推一个公式，两端都算一遍看自洽

## 第四章：消融实验 — 找到最优训练配方

### 4.1 实验设计

验证"物理预训练到底值多少钱"，四组对比：

| 消融 | 训练方式 | 测什么 |
|------|---------|--------|
| A | PINN 预训练，不微调 | 物理方程天花板 |
| B | PINN 起点 + 纯 MSE 微调 | 当前配方 |
| C | PINN 起点 + MSE + 物理约束 | 物理+数据互补 |
| D | 随机初始化 + 纯 MSE | PINN 预训练价值 |

**公平性保证**：同一模型架构、同优化器/lr、同 5 折分组（seed=123）、同评估指标（val delta K）、训练中保存最佳权重防过拟合。**B 和 B 对比**。

### 4.2 关键结果

| 消融 | delta | 发现 |
|------|-------|------|
| A | 10.72K | 物理方程基线：不够准 |
| B | 5.78K | PINN 预训练有用 |
| C | 6.85K | **加了物理反而更差！** |
| D | 5.40K | **随机初始化赢了** |

### 4.3 C < B 的原因分析

DeepOHeat 与 3D-ICE 的热源表达差异是候选解释之一；损失尺度、权重和优化梯度冲突也可能导致差异，不能由旧实验唯一归因。

**审慎表述**：旧设置在 200 cases 下没有观察到物理损失收益。它是否来自方程失配、权重或优化，需要修订实验区分，不能泛化成“物理约束有害”。

### 4.4 数据量决定价值

| 数据量 | PINN 价值 | 最优方案 |
|--------|----------|---------|
| 10/20 | 待 10 次成对重复实验 | 待正式结果 |
| 50/100/200 | 待 5 次成对重复实验 | 待正式结果 |

**待检验问题**：配方是否随数据量变化。只有正式工作站结果的置信区间和多重比较校正通过后，才能写方向性结论。

## 第五章：冷却模式扩展 — 从固体到四模

### 5.1 为什么需要多种模式

成品工具不能只会一种冷却。三种新模式的物理约束：

| 模式 | k | 顶面 BC | 底面 BC | Tamb | 物理特征 |
|------|---|---------|---------|------|---------|
| Solid | 0.1 | 绝热 | HTC=500 | 298K | 已有 200 case |
| Air | 0.1 | HTC=50 | HTC=500 | 313K | 顶面弱对流 |
| Liquid | 0.1 | HTC=5000 | HTC=500 | 293K | 顶面强对流 |
| Microchannel | 130 | 微通道插件 | HTC=500 | 293K | 真实硅 + 流体 |

### 5.2 技术路线

1. **3D-ICE heatsink 插件**：写 Python 脚本模拟微通道流体换热（Nu=4.36 层流、冷却液沿流向升温），编译 C++ loader
2. **统一 case 生成器** `gen_cases_all.py`：同一批芯片布局、不同 BC，四种模式各 80 case
3. **统一训练脚本** `run_cooling_parallel.py`：自动适配初始化方式（<50 case PINN，>100 case 随机）

### 5.3 关键发现

- **Air/Liquid 30 case 时被迫用 PINN**，精度 10-12K，不够好
- **扩到 80 case 后用随机初始化**，大幅改善
- **Microchannel 精度极高（0.6K）**：硅导热快，温度场几乎均匀，学习难度低
- **GPU 利用率 40% 是正常的**：模型 689K 参数，4090 算力过剩

## 第六章：多分支架构 — 一个模型的四种能力

### 6.1 问题

四种模式分开训四个模型：部署时用户得先选模式再加载对应模型——不优雅。

### 6.2 方案

MultiBranchDeepONet 架构：

```
                      ┌─ branch_solid ─┐
输入 (功率图+模式标签) ─┼─ branch_air ───┼─→ Hadamard × Trunk → 温度
                      ├─ branch_liquid ─┤
                      └─ branch_micro ──┘
```

- Trunk：四种模式共享——空间特征通用
- Branch：每种模式独立——功率→温度映射因冷却不同而异
- 模式标签当开关：liquid 进来只走 liquid 分支

### 6.3 训练策略

20 个独立任务（4 模式 × 5 折），4 张 GPU 抢活干。每任务独立训，跑完取每模式最优折的 branch 权重合并。

**合并逻辑**：所有分支共用同一个 Trunk，各自独立的 Branch。合并不是蒸馏——是直接的权重拼接。

### 6.4 结果

| 模式 | 最佳 delta | Branch 权重 |
|------|-----------|------------|
| Solid | ~5.4K | 独立 × 200 case |
| Air | ~6K | 独立 × 80 case |
| Liquid | ~7K | 独立 × 80 case |
| Microchannel | ~0.6K | 独立 × 80 case |

一个模型文件（`model_final.pth`），四个模式任意切换。输入功率图 + 冷却标签，输出 3D 温度场。

## 第七章：成果与展望

### 7.1 已完成

| 里程碑 | 成果 |
|--------|------|
| 归一化公式 | 4 项完整推导，论文+代码交叉验证 |
| PINN 预训练 | 2000 epochs 完成，基线 10.72K |
| 消融实验 A/B/C/D | 4 组对比，发现 B > C 的物理解释 |
| 最优配方 | 200 case 下随机初始化+纯监督最优 (5.40K) |
| 冷却模式 | 四种模式（固体/风冷/液冷/微通道），各 80-200 case |
| 多分支模型 | 一个模型文件，四种模式任意切换 |
| 3D-ICE 数据管线 | 自动化生成 → 仿真 → 训练全流程 |
| 工作站迁移 | 4×4090，一键运行脚本 |

### 7.2 核心洞察

1. **归一化在代码里，不在论文里**
2. **PINN 预训练的价值随数据量递减**——有足够数据时，随机初始化更好
3. **物理+监督不一定优于纯监督**——取决于两套物理模型是否一致
4. **模型架构和训练目标是分离的**——同一个 DeepONet，换 loss 就换行为
5. **多分支 > 多模型 > 四合一一个大模型**——分支隔离让各模式不互相拖累

2. **数据集丰富**：加更多参数组合（不同芯片尺寸、不同 HTC）
3. **论文写作**：核心实验表 + 数据量-物理价值曲线 + 四模式对比
4. **液冷深度研究**：用 3D-ICE heatsink 插件建模真实散热器型号
